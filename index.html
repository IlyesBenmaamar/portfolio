Data engineering · AI systems · Shipping markets

Data systems, with AI as the control layer.

A multi-source market-data pipeline, a visual workspace for steering agents, and a portable operating system that connects them. APIs, scrapers, browser handoffs and source workbooks all enter one governed path to inspected, evidence-backed outputs.

I engineered the system and directed the agents that built it. I translated real analytical work into an architecture, decomposed it into bounded tasks, controlled the agents' context and permissions, and defined the evidence required for acceptance. I reviewed, challenged and redirected the implementation against real data and working practices. Claude Code and Codex generated the code; the domain reasoning, orchestration and final judgement were mine.

2 · The work

The data pipeline

A monthly market-data system built on the medallion pattern. National customs statistics, licensed vessel movements, a licensed chemical-trade dataset and government energy statistics arrive through different routes, but each is preserved in bronze, conformed in silver and exposed as analysis-ready gold tables and workbooks.

Country trade statistics

Customs

National customs statistics arrive via official APIs, scrapers and browser handoffs, each country in its own format and on its own schedule. Every route is followed by schema and period validation.

API · browser automation · scraper · validated handoff
Observed vessel movements

Vessel flows

Raw trade-flow partitions from a licensed vessel-flow feed are ingested from a drop zone, preserved with lineage and transformed into consistent product, route and period tables.

Partitioned source files · incremental drop-zone refresh
Chemical-gas trade

Chemical trade

Periodic releases of a licensed chemical-trade dataset and a controlled country mapping are normalised into monthly and annual route tables for chemical-gas analysis.

Workbook ingestion · mapping · route transformation
Energy movements

Energy statistics

The latest monthly release of government energy statistics is reconciled with the local master, converted from barrels to tonnes and appended into the canonical store with source attribution.

Monthly spreadsheet release · master update · unit conversion

How it is checked

Twelve connectors cover six acquisition methods: four official APIs, three scrapers, a browser handoff, a portal download, a drop zone and two licensed feeds. Every connector is tested offline on small made-up fixtures, and the build fails closed on any quality or reconciliation breach. Code available on request.

    5 · The control layer

    The AI Operating System

    The portable layer between human judgement, AI agents and real data work. It defines what context matters, what an agent may do, how work is checked and how a useful method becomes reusable. Harbour View makes those controls visible and enforces them in software.

    Small contractA few lines, always loaded. Everything else is a skill, loaded on demand.
    Keep context minimal

    A short shared contract, with methods as skills retrieved only when the task calls for them.

    Evidence before "done"

    Validation proportionate to how reversible a change is and how far it reaches; skipped checks are stated.

    No inferred permission

    External writes, destructive changes and communication are never assumed. Harbour View's gate is this rule made concrete.

    Learning is reviewed

    A correction becomes a candidate with evidence and scope; persistent instructions change only after a review decision.

    Noticed"I keep losing work when the context fills, especially across different AIs."
    CandidateProposal 0001: checkpoint to a task branch with a handoff note any agent can read.
    ReviewedAccepted, with one standing exception: checkpoint commits on a task's own branch need no asking.
    In forceA context-handoff skill in the operating system; meters, checkpoints and the switch to Codex in Harbour View (D16).
    What the system contains

    The portable layer: ten conditional skills, five provider-neutral schemas, Codex and Claude adapters, decision proposals, synthetic evaluations, worked control records and automated validation. It also explains the authorship model: I designed the system and directed the work; AI agents generated the implementation. Code available on request.

    6 · Record

    Decision log

    Every significant choice is written down as it is made: the decision, why, and what evidence would reopen it. Reversals are marked rather than deleted. This is the record the AI agents read before they change anything.

    7 · Build

    Harbour View's build

    The interaction model was agreed by clicking through a prototype first, then built in seven steps, each ending in something I could open and try on a demo repository before it touched real work.

      Systems design and agent direction

      I did not pass a broad idea to an AI and accept whatever came back. I designed the operating model, divided the work into controlled pieces, inspected the evidence and remained accountable for what entered the system.

      • Turned operational data problems into specifications, interfaces and testable acceptance criteria.
      • Decomposed the build into bounded tasks and steered Claude Code and Codex with the context each task required.
      • Set the authority model: agents work freely on a copy, but commands, external access and changes to real files pass explicit gates.
      • Reviewed plans before implementation and required evidence before accepting completion.
      • Tested outputs against the real pipeline, Excel workflows and failure conditions, then redirected agents when the result was unsafe, generic or operationally wrong.
      • Recorded every significant product and engineering decision, including why each choice was made and what evidence would reopen it.
      • Converted successful methods into reusable skills, provider-neutral schemas and control records that work across agents.
      • Kept the layers separate: company data stays in the pipeline, the workspace remains generic, and the operating system stays portable.
